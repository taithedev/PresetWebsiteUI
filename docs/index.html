01 / GET STARTED

Start creating, right away.

Preset UI works as a static website. You don't need React, a database, an account or an API key. The code viewer, complete ZIP exports and theme tools work when the site runs from a local HTTP server or compatible static hosting.

01

Clone the project

Download the open repository locally. All components are organized under assets/data/.

02

Start a local server

Serve the project root using Python, VS Code Live Server or another static server.

03

Explore and export

Open the browser, inspect any component and use Export .zip for portable HTML, CSS and JavaScript.

TERMINAL / LOCAL SETUP
git clone https://github.com/taithedev/PresetWebsiteUI.git
cd PresetWebsiteUI
python -m http.server 8000
# http://localhost:8000

Opening index.html directly from a file:// URL may show the gallery, but browser restrictions can block source fetching and ZIP exports. Localhost or static hosting is the supported workflow.

02 / WORKFLOW

Real source, not mockups.

Click any component to open its inspector. Try the example in a sandboxed live preview, inspect HTML/CSS/JS, copy the markup or download a working source archive.

📦 my-component.zip
└── 📁 my-component/
　　├── index.html — runnable markup
　　├── styles.css — core kit + theme tokens
　　├── script.js — demo interactions
　　├── component.json — reusable catalog entry
　　└── README.md — usage instructions

Use Download whole kit on the Components page for every component as individual HTML examples alongside a shared stylesheet, interaction script and catalog JSON.

03 / FOUNDATIONS

A system of light and depth.

Every element uses a small CSS token vocabulary. In the Playground, adjust bloom, radius and accent color. Copy the generated CSS or save a JSON token file.

CSS / THEME OVERRIDES
:root {
  --ui-bg: #10111c;
  --ui-surface: #191a28;
  --ui-text: #f5f4fc;
  --ui-accent: #ad96ff;
  --ui-rgb: 173 150 255;

}

The base design uses near-black layered surfaces, Space Grotesk headlines, DM Sans text, hairline borders and bloom that stays behind legible content. The reusable component primitives are defined in assets/css/kit.css ↗.

05 / CUSTOMIZATION

Bring your own components.

Import component JSON in the Components view. Imported entries are stored in this browser's local storage and can be previewed and exported alongside built-in components. Custom JavaScript executes only inside a sandboxed, opaque-origin preview frame, not in the studio application itself.

JSON / IMPORT FORMAT
{
  "id": "my-button",
  "title": "My Button",
  "description": "A custom action component",
  "html": "<button class='ui-btn'>Hello</button>",
  "css": ".ui-btn { letter-spacing: .02em; }",
  "js": ""
}

Import is limited by browser storage capacity and a 180 KB JSON file size. Imported content is user-provided code: only import files you understand and trust. Preview frames cannot access the parent page, but imported HTML may still request remote resources.

06 / COMPOSITIONS

Build bigger, faster.

Patterns combine multiple primitives into larger compositions: a SaaS hero, login form, pricing comparison and dashboard. Download a pattern ZIP or copy its HTML to use as a starting point. A demo login validates input locally; it does not supply production authentication. Connect your own backend and validation.

07 / FILE WORKSPACE

Bring any file. Keep the folders.

The file workspace lets you add arbitrary file types, import directories, create nested folders, safely preview text files, download originals, remove stored files and export a folder as ZIP.

Local-firstFiles are stored in your browser using IndexedDB, not on a server.
OrganizedKeep folder paths for project assets and file collections.
PortableDownload originals or ZIP entire folders when needed.

This is not cloud backup or cross-device sync. Clearing site data can permanently remove stored files. Individual files are limited to 20 MB and upload batches to 80 MB; browser quota may be lower. Always export important files.

08 / CODING ASSISTANTS

Make it a real AI reference.

Point coding assistants at this repository and supply the AI_REFERENCE.md file. The machine-readable design-tokens.json and llms.txt give additional structured context.

PROMPT / SHARE WITH AN AI CODING ASSISTANT
Use https://github.com/taithedev/PresetWebsiteUI
as the visual reference for my application.
Read AI_REFERENCE.md and assets/css/kit.css first.
Adapt the layered dark surfaces, tasteful bloom,
rounded controls, typography and component primitives.
Preserve my existing routes, backend and real features.
Make the UI responsive, keyboard accessible, and
respect prefers-reduced-motion. Implement real behavior,
not nonfunctional screenshots. If you cannot access
the repo, ask for the source files.

Links are references, not access grants. An AI system that cannot browse GitHub must be given the source text explicitly. Apply the style to the user's own product rather than reproducing protected third-party brands.

09 / QUALITY

Beautiful and usable.

  • Use real buttons, labels, focus indicators and appropriate HTML semantics.
  • Support mouse, touch, and keyboard; modal previews use a native dialog.
  • Use adequate contrast, including inside translucent surfaces.
  • Support prefers-reduced-motion; don't animate essential information.
  • Keep demonstrations clearly labeled as demos and connect real backends separately.
  • Test at narrow viewport widths and with text scaling.
  • Minimize blur layers and favor transform/opacity animation for performance.
10 / SHIP IT

Host anywhere static.

Preset UI can run on GitHub Pages, Netlify, Vercel, or other static hosts. The repository requires no build command. Paths are relative so it also supports hosting at a repository subpath.

GitHub Pages setup: Settings → Pages → Deploy from a branch → main → /(root). Verify your deployment URL before sharing it. Repository commits do not automatically prove that a website is published.
